02Menjalankan proyek

Kode sudah lengkap, tetapi Racik butuh database. Urutan di bawah hanya perlu dilakukan sekali.

  1. Buat project Supabase (paket gratis cukup) di supabase.com. Dari pengaturan API project, salin Project URL dan publishable key (di dasbor lama disebut anon key).

  2. Buat tabel. Buka SQL Editor, tempel isi supabase/schema.sql, lalu Run. Ulangi dengan supabase/seed.sql untuk enam resep contoh.

  3. Matikan konfirmasi email selama pengembangan di pengaturan Authentication → provider Email → Confirm email. Kalau tetap menyala, akun baru harus mengklik tautan di email dulu sebelum bisa masuk (aplikasi sudah menangani kasus ini dengan dialog "Cek email Anda").

  4. Isi kunci. Salin env.example.json menjadi env.json di folder proyek, lalu isi dua nilainya. env.json sudah dimasukkan ke .gitignore.

    {
  "SUPABASE_URL": "https://xxxxxxxxxxxx.supabase.co",
  "SUPABASE_KEY": "sb_publishable_xxxxxxxxxxxxxxxxxxxx"
}

  5. Jalankan di HP Android (USB debugging aktif) atau emulator.

    flutter pub get
flutter run --dart-define-from-file=env.json

    Supaya tombol ▶ di VS Code juga memakai kunci ini, buat .vscode/launch.json dengan "args": ["--dart-define-from-file=env.json"].

  6. Buat admin pertama. Daftar akun lewat aplikasi, lalu jalankan di SQL Editor:

    update public.users set role = 'admin' where username = 'username_anda';

    Keluar lalu masuk lagi: aplikasi otomatis berganti ke tampilan Admin.

Tanpa model AISelama assets/models/ belum berisi model, fitur pindai berjalan dalam mode demo: tebakannya diturunkan dari isi byte foto dan selalu diberi pita "Mode demo". Seluruh alur — kamera, skor fuzzy, simpan riwayat, statistik — tetap bisa dicoba. Cara memasang model ada di Bab 10.

04Dart yang dipakai

Tidak perlu menguasai seluruh bahasa Dart sebelum mulai. Bab ini hanya membahas fitur yang benar-benar muncul di racik_app, masing-masing dengan contoh dari kodenya.

Null safety: ?, !, dan ??

Di Dart, variabel tidak boleh bernilai null kecuali tipenya diberi tanda tanya. Aturan ini selaras dengan ERD: kolom bertanda NN (not null) menjadi tipe biasa, kolom tanpa NN menjadi tipe bertanda ?. Operator ! berarti "saya yakin ini tidak null", dan ?? memberi nilai cadangan.

Kelas, constructor bernama, dan factory

Setiap model punya factory fromMap — constructor khusus yang membuat objek dari Map JSON hasil Supabase. Parameter bertanda required wajib diisi saat membuat objek, jadi lupa mengisi kolom NN langsung tertangkap sebelum aplikasi berjalan.

async, await, Future, dan Stream

Semua hal yang butuh waktu — query database, memotret, menjalankan model AI — mengembalikan Future: janji bahwa hasilnya akan datang nanti. await menunggu janji itu tanpa membekukan layar. Stream adalah Future yang datang berkali-kali; Racik memakainya untuk mendengar perubahan status login (onAuthStateChange).

Record dan destructuring

Record adalah "tuple" bawaan Dart: beberapa nilai dibungkus tanpa perlu membuat kelas. NutritionCard memakainya untuk daftar baris nutrisi, lalu membongkarnya kembali di dalam for.

Switch expression

Switch yang menghasilkan nilai. Dart memeriksa bahwa semua nilai enum sudah ditangani — kalau kelak Anda menambah aktor baru dan lupa membuat layarnya, kode tidak bisa dikompilasi.

Collection if, for, dan spread ...

Di dalam list widget, Anda boleh menulis if dan for langsung. Widget di bawah hanya muncul bila resep punya waktu masak. Dengan ...[ ], beberapa widget sekaligus bisa disisipkan di bawah satu syarat.

JenisKapan dipakaiContoh di Racik
StatelessWidgetTampilan hanya bergantung pada data yang diterima dari luarNutritionCard, FoodCard, HealthScoreBadge, ProfileScreen

Siklus hidup State

Empat method yang akan Anda temui di hampir setiap layar:

  • initState() — dipanggil sekali saat widget muncul. Tempat memulai query awal.
  • didChangeDependencies() — dipanggil setelah initState dan setiap kali InheritedWidget yang dipakai berubah (tema, ukuran layar). Tidak dipakai di Racik, tetapi sering muncul di tutorial lain.
  • build() — dipanggil setiap kali tampilan perlu digambar ulang (bisa puluhan kali). Jangan memulai query di sini.
  • dispose() — dipanggil saat widget dibuang. Lepaskan TextEditingController, Timer, dan kamera di sini.

Satu aturan lagi yang sering terlupa: setelah await, layar bisa saja sudah ditutup pengguna. Selalu periksa mounted sebelum memakai context atau memanggil setState.

FutureBuilder — menampilkan data yang sedang dimuat

FutureBuilder membangun tampilan berbeda untuk tiap tahap Future: sedang memuat, gagal, atau selesai. Jebakan paling umum: membuat Future di dalam build(). Karena build() berjalan berulang kali, query ikut terkirim berulang kali. Simpan Future di State.

Navigator — pindah layar dan membawa hasil pulang

Navigator.push membuka layar baru; Navigator.pop menutupnya — dan boleh membawa nilai kembali ke layar sebelumnya. Layar kamera memakai pola ini: ia tidak tahu apa yang akan dilakukan pada foto, ia hanya mengembalikan byte-nya.

Varian lain yang dipakai: pushReplacement (Login ↔ Daftar, agar tidak menumpuk) dan popUntil((route) => route.isFirst) (kembali ke layar utama setelah login).

07Supabase & keamanan

ERD Anda memakai tipe khas PostgreSQL (uuid, timestamptz, numeric), dan tabel users-nya tidak punya kolom email maupun password. Keduanya cocok dengan Supabase: database Postgres plus layanan login (Auth) dan penyimpanan file (Storage) dalam satu paket.

Kenapa users tidak punya password?

Email dan hash password disimpan Supabase Auth di tabel terpisah (auth.users) yang tidak bisa dibaca aplikasi. Tabel public.users milik Anda hanya menyimpan profil, dan id-nya sama dengan id akun Auth. Barisnya dibuat otomatis oleh trigger setiap ada pendaftaran:

Tulis penjelasan ini di laporan, supaya penguji tidak mengira kolom password terlupa.

Row Level Security: hak akses per aktor

Kunci Supabase di aplikasi (publishable key) boleh terlihat siapa saja — yang menjaga data adalah Row Level Security (RLS): aturan di database yang memeriksa setiap baris sebelum dibaca atau diubah. Aktor use case Anda terpetakan langsung ke aturan-aturan itu.

TabelGuestPenggunaAdmin
users—baca & ubah profil sendiri, kecuali role dan is_activebaca & ubah semua
foodsbaca yang terverifikasibaca yang terverifikasibaca, tambah, ubah, hapus semua
nutritions, steps, food_ingredients, ingredientsbacabacasemua
scan_history—baca, tambah, hapus milik sendiribaca semua (statistik)
favorites—semua, milik sendirimilik sendiri
Storagelihat lewat URL publikunggah ke folder <user_id>/+ unggah foto resep

is_admin() adalah fungsi SQL yang memeriksa role = 'admin' dan is_active milik orang yang sedang login. Fungsi ini security definer agar bisa membaca tabel users tanpa terjebak aturan RLS tabel users itu sendiri.

Query dengan join

Supabase membuat REST API otomatis dari tabel Anda (PostgREST). Relasi di-join dengan menulis nama tabel anak di dalam select; Supabase mengikuti foreign key yang sama dengan garis di ERD.

Yang dikerjakan database (Function, Trigger, dan Procedure)

Operasi penting dipindahkan ke level database untuk menjamin integritas dan keamanan data:

  • Stored Functions: username_available(text) memeriksa ketersediaan username saat registrasi tamu lewat RPC, dan is_admin() memvalidasi peran admin aktif untuk aturan RLS (keduanya bertipe security definer).
  • Trigger: handle_new_user otomatis mengisi profil di public.users saat user baru mendaftar di Auth; protect_user_access_columns mencegah manipulasi hak akses profil; dan increment_scan_count otomatis menaikkan counter foods.scan_count.
  • Stored Procedures: sp_verify_food(food_id, admin_id) untuk verifikasi resep oleh admin, serta sp_clear_user_history(user_id) untuk menghapus seluruh riwayat pindai akun tertentu.
  • Pesan error: kode error PostgreSQL diterjemahkan friendlyError() di lib/core/errors.dart (misalnya 23505 untuk data kembar, 23503 jika data masih berelasi, dan 42501 untuk izin ditolak).

08State & peran pengguna

State adalah data yang bisa berubah saat aplikasi berjalan. Data yang hanya dipakai satu layar cukup disimpan di State layar itu dengan setState. Data yang dipakai banyak layar — siapa yang sedang login — disimpan di Provider.

app.dart menaruh semua service dan provider di puncak pohon widget. Layar mana pun bisa mengambilnya tanpa dioper dari layar ke layar lewat constructor.

Tiga cara mengambil provider

CaraArtinyaContoh
context.read<T>()Ambil sekali, tidak berlangganan. Untuk event handler dan initState.Tombol Masuk memanggil read<AuthProvider>().login()
context.watch<T>()Berlangganan: build() diulang setiap provider memanggil notifyListeners().AuthGate; tombol yang menampilkan loading saat isBusy
context.select<T, R>()Berlangganan pada satu nilai saja.Riwayat hanya bereaksi saat id pengguna berubah

Dua hal yang perlu diperhatikan. Pertama, watch dan select hanya boleh dipanggil di dalam build(); provider melempar error bila select dipanggil di initState atau didChangeDependencies. Kedua, Future di sini memang dibuat di build() — pengecualian yang disengaja dari aturan di Bab 5, karena dijaga if sehingga query hanya terkirim saat id pengguna berubah.

Dari aktor use case ke layar

AuthProvider mendengarkan onAuthStateChange dari Supabase. Setiap kali status login berubah, ia membaca profil dari tabel users lalu menentukan aktor. AuthGate (switch expression di Bab 4) memilih kerangka layar berdasarkan aktor itu.

09Use case satu per satu

Setiap subbab menyebut konsep Flutter yang paling banyak dipelajari dari use case itu. Urutannya mengikuti diagram: Guest, Pengguna, lalu Admin.

Mendaftar Akun

  • Form
  • TextFormField + validator
  • RPC Supabase

Form dengan GlobalKey<FormState> memvalidasi semua isian sekaligus lewat _formKey.currentState!.validate(). Batas panjang mengikuti ERD (username varchar(50), full_name varchar(100)). Sebelum mendaftar, aplikasi memanggil fungsi SQL username_available — tamu belum login, jadi tidak boleh membaca tabel users secara langsung. Nama dan username dikirim sebagai metadata; trigger di Bab 7 yang memasukkannya ke tabel.

Melakukan Login

  • mounted
  • popUntil

Layar login tidak memutuskan ke mana pengguna pergi setelah berhasil. Ia cukup menutup diri; AuthGate yang mendengar perubahan di AuthProvider akan menampilkan MainShell atau AdminShell. Kodenya ada di Bab 5.

Mencari Resep

  • Timer (debounce)
  • ChoiceChip
  • RefreshIndicator

Pencarian berjalan saat pengguna mengetik, tetapi ditunda 400 ms sampai ketikan berhenti — kalau tidak, kata "rendang" mengirim tujuh query. Filter kategori memakai ChoiceChip, dan tarik-ke-bawah memuat ulang lewat RefreshIndicator.

Melihat Detail Resep

  • FutureBuilder
  • Sliver
  • widget dipakai ulang

Dua use case <<include>>-nya menjadi tiga widget yang disusun berurutan. Widget-widget ini tidak tahu apa pun tentang Supabase: mereka hanya menerima data lewat constructor, sehingga bisa dipakai lagi di layar hasil pindai.

Memindai Makanan

  • camera
  • WidgetsBindingObserver
  • image_picker
  • pipeline

Use case terpenting Racik, dan satu-satunya yang punya dua tingkat <<include>>. Seluruh alurnya dikumpulkan di satu kelas, ScanPipeline, supaya layar tetap sederhana dan urutannya bisa dibaca dari atas ke bawah.

Kamera

CameraController harus diinisialisasi sebelum dipakai dan dilepas sesudahnya; kalau lupa, kamera terkunci untuk aplikasi lain. Saat aplikasi ke latar belakang (misalnya ada telepon masuk), kamera dilepas, lalu dibuka lagi saat kembali. Informasi itu datang dari WidgetsBindingObserver.

Kamera sengaja tidak dibuka langsung di tab Pindai. Tab itu berisi dua tombol besar (Buka kamera, Pilih dari galeri) lalu petunjuk memotret; kamera baru menyala di layar penuh terpisah dan otomatis mati saat layar itu ditutup. Izin kamera diminta saat initialize() dipanggil, dan penolakan izin ditampilkan sebagai pesan yang menjelaskan cara mengaktifkannya.

Mengidentifikasi Citra Makanan

Dikerjakan FoodRecognizer — dibahas lengkap di Bab 10.

Menampilkan Detail Skor Kesehatan dan Informasi Nutrisi

  • ExpansionTile
  • widget dipakai ulang

Layar hasil menampilkan foto, nama makanan beserta tingkat keyakinan AI, HealthScoreCard, dan NutritionCard yang sama dengan detail resep. Kata "Detail" di nama use case diwujudkan dengan bagian yang bisa dibuka, "Mengapa skornya segini?": derajat keanggotaan setiap zat gizi dan aturan fuzzy terkuat. Cara menghitungnya ada di Bab 11.

Melihat Hasil Pemindaian Makanan

  • join foods(name)
  • Key

Daftar riwayat mengambil scan_history milik pengguna beserta nama makanannya dalam satu query. Karena tab memakai IndexedStack (state tiap tab dijaga), riwayat tidak otomatis memuat ulang setelah pindai baru. Solusinya: beri widget riwayat Key baru setiap tabnya dibuka. Flutter menganggap widget dengan Key berbeda sebagai widget baru, sehingga state lamanya dibuang.

Mengubah Profil Akun

  • image_picker
  • Storage
  • copyWith

Foto dipilih dari galeri, diunggah ke bucket avatars di folder bernama id pengguna, lalu URL publiknya disimpan ke avatar_url. Model AppUser tidak pernah diubah langsung: copyWith() membuat salinan dengan beberapa field berbeda — pola umum untuk data yang tidak boleh berubah diam-diam.

Mengelola Data Resep

  • form dinamis
  • upsert
  • DropdownButtonFormField

Satu formulir mengisi empat tabel sekaligus: foods, nutritions, food_ingredients, dan steps. Baris bahan dan langkah bisa ditambah dan dihapus; masing-masing punya TextEditingController sendiri yang ikut di-dispose. Nutrisi disimpan dengan upsert karena relasinya 1 : 1, sedangkan daftar anak cukup dihapus lalu diisi ulang.

Verifikasi dilakukan dari menu ⋮ di daftar resep; setVerified() mengisi is_verified, verified_by, dan verified_at sekaligus. Resep yang belum diverifikasi tidak terlihat oleh Guest dan Pengguna — aturan RLS di Bab 7.

Mengelola Data Bahan

  • showDialog
  • pop dengan nilai

Dialog tambah/ubah bahan mengembalikan objek Ingredient lewat Navigator.pop — pola yang sama dengan kamera. Bahan yang masih dipakai resep tidak bisa dihapus (ON DELETE RESTRICT), dan pesan errornya sudah diterjemahkan.

Melihat Statistik Pemindaian Pengguna

  • Future.wait
  • grafik tanpa paket

Empat query dikirim bersamaan dengan Future.wait, bukan satu per satu, sehingga waktu tunggunya sama dengan query paling lambat. Data 7 hari terakhir dijumlahkan di Dart. Diagram batangnya hanya Container yang tingginya sebanding dengan jumlah pindai — cukup untuk belajar, tanpa paket grafik.

Mengelola Akun Pengguna

  • Switch
  • SimpleDialog

Admin bisa mengubah peran dan menonaktifkan akun. Menghapus akun Auth butuh secret key yang tidak boleh ada di aplikasi, jadi "hapus" diwujudkan sebagai nonaktif. Admin tidak bisa menonaktifkan dirinya sendiri agar tidak terkunci.

10Model AI (TFLite)

Racik mengenali makanan di dalam HP memakai TensorFlow Lite. Keuntungannya: bekerja tanpa internet, cepat, gratis, dan foto tidak perlu dikirim ke server untuk dikenali. Konsekuensinya: model hanya mengenal makanan yang ada saat pelatihan, dan Anda yang harus melatihnya.

Melatih model dengan Teachable Machine

  1. Buka Teachable Machine (teachablemachine.withgoogle.com) → Image Project → Standard image model.

  2. Buat satu class per makanan. Nama class harus sama persis dengan foods.name di database — misalnya Nasi Goreng — karena hasil tebakan dicocokkan ke resep lewat nama (huruf besar/kecil boleh beda).

  3. Isi setiap class dengan foto yang beragam: sudut, cahaya, piring, dan latar berbeda. Makin banyak dan makin beragam, makin baik. Tambahkan satu class Bukan makanan berisi foto meja, tangan, dan ruangan; label ini tidak ada di foods, sehingga hasilnya menjadi "tidak ditemukan" alih-alih menebak asal.

  4. Train Model → Export Model → tab Tensorflow Lite → Floating point → Download. Zip-nya berisi file .tflite dan labels.txt.

  5. Ganti nama file .tflite menjadi racik_food.tflite, lalu taruh bersama labels.txt di assets/models/. Jalankan ulang aplikasi (bukan hot reload). Pita "Mode demo" akan hilang.

Cara kodenya bekerja

Model menerima gambar persegi berukuran tetap (umumnya 224 × 224 piksel, tiga kanal warna) dan mengeluarkan satu angka keyakinan untuk setiap label. Karena itu foto harus diproses dulu: dipotong tengah, dikecilkan, lalu setiap nilai piksel dinormalisasi ke rentang −1 sampai 1 seperti saat pelatihan.

Mengolah 50.176 piksel cukup berat untuk dikerjakan di thread UI, jadi Isolate.run memindahkannya ke thread lain. Ukuran input dan tipe data (float atau kuantisasi) dibaca dari model itu sendiri, sehingga kode tidak perlu diubah bila model diganti.

Hasilnya diurutkan dan tiga teratas dikembalikan. Tebakan pertama dipakai, dua lainnya ditampilkan sebagai "Kemungkinan lain". Bila keyakinan tertinggi di bawah AppConfig.confidenceThreshold (0,60), status pindai menjadi tidak_yakin dan pengguna diberi saran memotret ulang.

Kenapa ada kelas abstrak FoodRecognizer?

Layar dan ScanPipeline hanya mengenal kontrak FoodRecognizer. Ada dua implementasi — TfliteFoodRecognizer dan DemoFoodRecognizer — dan loadFoodRecognizer() memilih yang pertama bila file model ada. Implementasi ketiga bisa ditambahkan tanpa mengubah satu layar pun, misalnya pengenal berbasis API cloud yang dipanggil lewat Supabase Edge Function. Pendekatan cloud juga bisa memperkirakan gizi makanan yang belum ada di database; hasilnya disimpan dengan foods.source = 'ai' dan is_verified = false sampai Admin memeriksanya. Kolom-kolom itu sudah ada di ERD Anda.

Kunci APIBila memakai API cloud, jangan pernah menaruh kuncinya di kode Flutter — APK bisa dibongkar. Simpan di Edge Function, lalu panggil dari aplikasi dengan Supabase.instance.client.functions.invoke().

11Skor kesehatan fuzzy

Batas "gula tinggi" tidak tajam: 11,9 gram tidak tiba-tiba sehat dan 12,1 gram tidak tiba-tiba berbahaya. Logika fuzzy mengizinkan satu nilai menjadi sebagian rendah dan sebagian sedang sekaligus. Racik memakai metode Sugeno orde-nol di lib/ai/fuzzy_health_score.dart — logika Dart murni tanpa Flutter, sehingga mudah dites.

Input dan himpunan fuzzy

Empat kolom nutritions dipakai sebagai input, semuanya per porsi. Tiap input dipetakan ke himpunan rendah, sedang, tinggi (serat hanya rendah dan tinggi).

InputKolomRendahSedangTinggi
Gulasugar_g1 sampai 5 g, 0 di 12 gsegitiga 5 – 12 – 25 g0 di 12 g, 1 mulai 25 g
Lemakfat_g1 sampai 5 g, 0 di 12 gsegitiga 5 – 12 – 21 g0 di 12 g, 1 mulai 21 g
Natriumsodium_mg1 sampai 300 mg, 0 di 600 mgsegitiga 300 – 600 – 1000 mg0 di 600 mg, 1 mulai 1000 mg
Seratfiber_g1 sampai 2 g, 0 di 5 g—0 di 2 g, 1 mulai 5 g

Aturan

Kombinasi himpunan menghasilkan 3 × 3 × 3 × 2 = 54 aturan. Daripada menulis 54 baris, konsekuen setiap aturan dihitung dengan rumus yang sama, sehingga tidak ada kombinasi yang terlewat:

z = 90 − penalti(gula) − penalti(lemak) − penalti(natrium) + bonus(serat)
penalti: rendah 0 · sedang 10 · tinggi 30    bonus serat tinggi: +10    z dibatasi 0–100

Kekuatan setiap aturan, α, adalah derajat terkecil dari keempat syaratnya (operator DAN = min). Skor akhir adalah rata-rata z yang dibobot α:

skor = Σ(α · z) ÷ Σα     ✓ Sehat ≥ 75   – Cukup Sehat ≥ 50   ! Kurang Sehat < 50

Logika yang tidak bergantung pada Flutter paling mudah dites — itulah alasan fuzzy dan model dipisahkan dari widget.

Tes widget dengan service palsu

Layar bergantung pada service, dan service bergantung pada Supabase. Supaya layar bisa dites tanpa internet, tes membuat service palsu dengan implements, lalu menaruhnya di MultiProvider yang sama seperti app.dart. Berkat noSuchMethod, cukup method yang dipakai layar yang perlu ditulis.

Tes ini tidak sekadar formalitas. Saat pertama dijalankan, ia menemukan tiga masalah nyata yang lolos dari flutter analyze, dan ketiganya sudah diperbaiki:

  • context.select di luar build(). Riwayat pindai semula memanggilnya di didChangeDependencies; provider melempar error dan tab Riwayat akan merah. Sekarang dipanggil di build() (Bab 8).
  • Dua FAB dengan hero tag yang sama. Tab Resep dan Bahan di Admin sama-sama punya FloatingActionButton; karena IndexedStack menyimpan keduanya, membuka formulir resep memicu error "multiple heroes that share the same tag". Solusinya: heroTag: 'fab-resep' dan heroTag: 'fab-bahan'.
  • Tombol "Buka kamera" terdorong keluar layar saat teks petunjuk panjang — persis yang dialami pengguna dengan ukuran huruf besar di HP kecil. Tombol dipindah ke atas petunjuk (Bab 12).

15Latihan

Cara tercepat memahami kode adalah mengubahnya. Latihan diurutkan dari yang paling ringan; setiap latihan menyebut file tempat memulai.

  1. Ganti warna identitas. mudah
    Ubah AppTheme.seed di core/theme.dart, simpan, lihat hot reload mewarnai ulang seluruh aplikasi.

  2. Hapus riwayat dengan menggeser. mudah
    Bungkus ListTile di scan_history_screen.dart dengan Dismissible dan panggil ScanService.delete().

  3. Simpan label tebakan AI. sedang
    Tambah kolom predicted_label di SQL, field di ScanHistory, isi di ScanPipeline, lalu tampilkan "label tanpa resep" di statistik Admin. Latihan ini menyentuh semua lapis dari Bab 3.

  4. Kalori sebagai input fuzzy kelima. sedang
    Tambah FuzzyVariable untuk calories, satu perulangan lagi di inferensi, dan penaltinya. Perbarui angka harapan di tes.

  5. Widget test pertama Anda. sedang
    Tulis tes yang memanggil tester.pumpWidget(MaterialApp(home: Scaffold(body: NutritionCard(...)))) lalu memastikan find.text('Protein') ditemukan. Contek pola app_smoke_test.dart.

  6. Foto pindai yang privat. sulit
    Jadikan bucket scan-images privat, simpan path (bukan URL) di image_url, lalu tampilkan foto dengan createSignedUrl().

  7. Inferensi di isolate. sulit
    Saat ini hanya pra-pemrosesan yang berjalan di isolate. tflite_flutter menyediakan IsolateInterpreter; pakai itu agar run() juga tidak menahan UI.

Widget

State

BuildContext
Posisi sebuah widget di pohon. Dipakai untuk mencari hal di atasnya: tema, Navigator, provider.

Nilai yang datang nanti, dan cara menunggunya tanpa membekukan layar.

Tumpukan layar. push menambah, pop menutup dan bisa membawa nilai.
Hot reload
Menyuntikkan kode baru ke aplikasi yang sedang berjalan tanpa kehilangan state.
Isolate
Thread terpisah di Dart, dipakai untuk pekerjaan berat agar UI tetap lancar.
Supabase
Layanan backend: PostgreSQL, Auth, Storage, dan REST API otomatis (PostgREST).

Row Level Security — aturan di database yang menentukan baris mana yang boleh dibaca atau diubah siapa.
Trigger
Fungsi SQL yang berjalan otomatis saat baris ditambah, diubah, atau dihapus.
Stored Function
Fungsi SQL yang mengembalikan nilai (return value), misalnya username_available.
Stored Procedure
Blok program SQL yang dipanggil dengan perintah CALL untuk menjalankan logika data, misalnya sp_verify_food.
RPC
Remote Procedure Call — memanggil fungsi atau prosedur SQL dari aplikasi.
Bucket
"Folder" utama di Supabase Storage tempat foto disimpan.

TensorFlow Lite, format model AI yang ringan untuk HP.

Defuzzifikasi
Mengubah hasil aturan-aturan fuzzy kembali menjadi satu angka tegas (skor).
Semantics
Keterangan yang dibaca pembaca layar seperti TalkBack.
